# Prometheus Operating System README

This is the single starting point for Prometheus founders, employees, contractors, consultants, Codex sessions, and future AI systems.

The goal of this operating system is simple:

Prometheus should become a company with repeatable systems, not a collection of ideas trapped inside one person's head.

## How To Use This Operating System

Start here before creating new documents, sending executive materials, changing the app, preparing pilots, discussing pricing, or onboarding contractors.

Use the folder that matches the job:

1. `01 Executive & Leadership`
2. `02 Pilot Program`
3. `03 Pricing & Revenue`

5. `05 Security & Compliance`
6. `06 LLC & Finance`
7. `07 Marketing & Social Media`

10. `10 Future Expansion`

Each folder explains:

- Purpose.
- Included documents.
- When each document should be used.
- Who should use it.
- What future documents belong there.

## Company Knowledge Rule

If something important is repeated more than twice, it should become a document, checklist, template, or playbook.

If only the founder knows how to do it, the company does not know how to do it yet.

## Sendable Vs Internal Materials

Sendable materials:

- `SENDABLE LEADERSHIP PACKET/`
- `output/pdf/Prometheus_IQ_Sendable_Leadership_Packet.pdf`

Internal materials:

- Pricing strategy.
- Founder notes.
- Competitive strategy.
- Product source code.
- Security audit details.
- Future roadmap.
- Patent or proprietary thinking.
- Raw field evidence unless approved for use.

When in doubt, keep the document internal until it is reviewed.

## Codex Session Instructions

Future Codex sessions should:

1. Start with this README.
2. Identify the correct operating folder.
3. Use existing documents before creating new ones.
4. Avoid duplicating material.
5. Keep sendable materials separate from internal strategy.
6. Never expose proprietary technology, source code, secrets, or sensitive customer data in public-facing documents.
7. Make small, practical improvements that support current business goals.

## Founder Decision Filter

Before adding work, ask:

- Does this help pilot approval?
- Does this help pilot success?
- Does this protect the company?
- Does this improve customer trust?
- Does this create proof?
- Does this make Prometheus more repeatable?

If the answer is no, it can probably wait.

## Operating Philosophy

Prometheus should operate like a serious company before it looks like a large company.

That means:

- Clean documents.
- Clear ownership.
- Protected data.
- Controlled pilots.
- Measured outcomes.
- Simple pricing.
- Strong founder rhythm.
- Repeatable systems.

The goal is not more paperwork. The goal is less confusion.
