# 3D Website Production Route

## Purpose

This is the repeatable route for building future 3D websites for Prometheus, pilot partners, or any company that wants a custom Prometheus-style website or demo experience.

## Core Approach

Use Spline for visual 3D scene creation when a no-code 3D editor is useful.

Use Codex and the Prometheus codebase for:

- Website structure.
- Responsive layout.
- Scroll behavior.
- Motion tuning.
- Text and positioning.
- Performance optimization.
- Security review.
- Cloudflare deployment preparation.
- Company-specific customization.

## When To Use This Route

Use this process when:

- Prometheus needs a premium public website.
- A pilot customer wants a custom visual demo.
- A future business wants its own branded 3D landing page.
- A sales presentation needs a cinematic, executive-quality web experience.
- The founder wants more movement, more 3D depth, or stronger visual impact.

## Production Steps

1. Define the business goal.
2. Define the audience.
3. Define what the website must make the viewer believe.
4. Create or plan the 3D scene in Spline.
5. Export or embed the Spline scene if appropriate.
6. Bring the scene into the coded website.
7. Use Codex to tune scroll movement, camera motion, lighting, text placement, mobile layout, loading behavior, and call-to-action flow.
8. Keep proprietary technology hidden.
9. Test desktop and phone layouts.
10. Deploy only after review.

## Prometheus Visual Standard

Future 3D websites should feel:

- Premium.
- Cinematic.
- Dark.
- Intelligent.
- Field-sales focused.
- Executive-ready.
- High motion without becoming confusing.

The visitor should understand the outcome, not the internal technology.

## What Spline Handles

Spline can help create:

- 3D logos.
- 3D objects.
- Animated scenes.
- Camera movement.
- Interactive visual elements.
- Embeddable 3D scenes.

## What Codex Handles

Codex handles:

- Code integration.
- Site sections.
- Button actions.
- Email/Instagram links.
- Responsive layout.
- Performance cleanup.
- Security checks.
- Cloudflare deployment packaging.
- Separate demo versions per company.

## Company-Specific Rule

Every company gets its own separate website/demo folder when needed.

Do not mix:

- Prometheus public website work.
- Anthony beta app work.
- Fitness Connection materials.
- Future customer demos.
- Customer-specific data or branding.

## Security Rule

Public websites should show:

- What Prometheus does.
- What outcome it creates.
- Why it matters.
- How a pilot works.

Public websites should not show:

- Source code.
- Route scoring logic.
- Proprietary intelligence logic.
- Internal prompts.
- Private customer data.
- GPS/user data.
- API keys or secrets.
