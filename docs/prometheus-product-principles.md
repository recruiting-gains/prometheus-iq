# Prometheus Product Principles

## Purpose

Prometheus IQ exists to help field representatives make better decisions with less effort. Every product decision should reduce wasted time, reduce uncertainty, and increase verified selling activity.

## Principles

### Maximum Intelligence

Prometheus should do the thinking before the representative reaches the screen. Scoring, ranking, validation, and route reasoning should happen behind the experience so the visible product can stay simple.

### Minimum Reading

Representatives should not have to read paragraphs while standing in a parking lot. Show the business, address, confidence, opportunity rating, nearby opportunities, directions, and logging action first. Move deeper reasoning behind optional detail controls.

### Maximum Selling

Every screen should help a representative decide where to go, who to ask for, what to log, or what to do next. If a detail does not improve selling action, hide it or remove it from the primary view.

### Field-First Design

Prometheus IQ must work in real field conditions: phones, glare, motion, interruptions, short attention spans, and fast decisions. Mobile clarity matters more than internal explanation density.

### Real Businesses Only

Route Intelligence should recommend only verified, direction-safe businesses. No placeholders, generic categories, vague destinations, or inferred business names should enter the representative route.

### Evidence Over Assumptions

Prometheus may estimate, but it must not pretend estimates are verified truth. Confidence should rise from field evidence, Google-qualified data, route history, and representative outcomes.

### One System

Do not create duplicate dashboards, duplicate route engines, duplicate learning engines, or parallel intelligence paths. Improve the existing production architecture.

### Explainability On Demand

The main experience should be fast. The reasoning should still be available when the founder, owner, or representative needs to understand why a recommendation was made.

### Every Feature Must Reduce Effort

A feature is only product-positive if it reduces representative effort, owner effort, or founder effort. More controls are not automatically better. More intelligence with fewer decisions is better.

## Operating Standard

Before future UI work begins, verify whether the capability already exists. Improve the existing system when possible. Preserve Route Intelligence, Google qualification, learning history, export, copy summary, and owner/representative separation.
